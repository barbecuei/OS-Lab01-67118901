2. I/O Bound Concept:

ผมเข้าใจว่า I/O Bound คือสภาวะที่โปรแกรมใช้เวลารอการอ่านหรือเขียนข้อมูลจากอุปกรณ์ I/O มากกว่าการประมวลผลด้วย CPU ทำให้ความเร็วในการทำงานถูกจำกัดด้วยการรับส่งข้อมูล
จากการทดลอง ผมพบว่าการอ่านไฟล์แยก 1,000 ไฟล์ใช้เวลา 0.0221 วินาที ขณะที่การอ่านไฟล์รวมเพียงไฟล์เดียวใช้เวลา 0.0023 วินาที ทำให้ผมเห็นว่าการจัดการไฟล์จำนวนมากมีภาระ I/O เพิ่มขึ้น
เมื่อโปรแกรมต้องรอข้อมูลจากดิสก์ CPU อาจไม่สามารถประมวลผลงานของโปรแกรมนั้นต่อได้ทันที จึงอาจว่างหรือเปลี่ยนไปทำงานของโปรเซสอื่นแทน ดังนั้นในกรณีที่ไม่มีงานอื่นพร้อมทำงาน CPU อาจมีการใช้งานต่ำ ไม่จำเป็นต้องทำงานที่ 100% แม้โปรแกรมจะยังทำงานไม่เสร็จก็ตาม


3. AI Industry Connection (Phase 3):

จากการทดลอง ผมพบว่าการอ่านไฟล์แยก 1,000 ไฟล์ใช้เวลา 0.0221 วินาที ส่วนการอ่านไฟล์รวมเพียงไฟล์เดียวใช้เวลา 0.0023 วินาที แม้ว่าทั้งสองวิธีจะอ่านข้อมูลปริมาณเท่ากันก็ตาม

เมื่อ Data Pipeline อ่านข้อมูลได้ช้า GPU ก็อาจต้องว่างรอ Batch ถัดไปแทนที่จะประมวลผลอย่างต่อเนื่อง ซึ่งเป็นปัญหา GPU Starvation และทำให้ระยะเวลาการเทรนโมเดลเพิ่มขึ้น
