1. FIFO vs LRU (Phase 2)

จากการทดลองรันโปรแกรมโดยกำหนดให้ RAM มี 3 Frames พบว่า FIFO เกิด Page Fault ทั้งหมด 9 ครั้ง ส่วน LRU เกิด Page Fault 7 ครั้ง
จากที่ผมสังเกต FIFO จะนำ Page ที่เข้ามาอยู่ใน RAM ก่อนที่สุดออก โดยไม่ได้สนใจว่า Page นั้นเพิ่งถูกใช้งานหรือไม่ เช่น เมื่อโปรแกรมเรียก Page 5 ในขณะที่ RAM เต็ม FIFO เลือกนำ Page 2 ออก ทำให้เมื่อโปรแกรมเรียกใช้ Page 2 อีกครั้งจึงเกิด Page Fault
ส่วน LRU จะเลือกนำ Page ที่ไม่ได้ถูกใช้งานมานานที่สุดออก โดยมีการอัปเดตลำดับทุกครั้งที่เรียกใช้ Page ในเหตุการณ์เดียวกัน LRU เลือกนำ Page 3 ออกแทน Page 2 เพราะ Page 2 เพิ่งถูกใช้งาน ทำให้เมื่อโปรแกรมเรียก Page 2 อีกครั้งจึงเกิด Page Hit
จากผลการทดลองนี้ ผมเข้าใจว่า LRU สามารถลด Page Fault ได้เมื่อโปรแกรมมีการเรียกใช้ Page เดิมซ้ำ ๆ เพราะอัลกอริทึมให้ความสำคัญกับประวัติการใช้งานล่าสุด ขณะที่ FIFO พิจารณาเพียงลำดับที่ Page ถูกโหลดเข้ามาใน RAM

2. Understanding Thrashing (Phase 3)

จากการทดลองผมเข้าใจว่า Thrashing คือสภาวะที่ระบบปฏิบัติการต้องสลับข้อมูลระหว่าง RAM กับดิสก์บ่อยมาก เนื่องจากหน่วยความจำไม่เพียงพอ ทำให้ระบบเสียเวลาไปกับการย้ายข้อมูลมากกว่าการประมวลผลงานจริง
จากผลการทดลองที่ 1 ใช้เวลาประมวลผล 0.4334 วินาที ส่วนการทดลองที่ 2 ใช้เวลา 1.9509 วินาที ซึ่งช้ากว่าประมาณ 4.5 เท่า
ผมสังเกตว่า การทดลองที่ 1 ประมวลผลข้อมูลใน RAM โดยตรง ขณะที่ การทดลองที่ 2 ต้องเปิดไฟล์ อ่านข้อมูล และเขียนข้อมูลกลับลงดิสก์ซ้ำ ๆ จึงใช้เวลามากกว่า ผลการจำลองนี้ทำให้ผมเข้าใจว่า หากระบบต้องสลับ Page ระหว่าง RAM กับดิสก์บ่อย ๆ ระหว่างการเทรน AI เวลาที่ใช้ในการเทรนจะเพิ่มขึ้น และประสิทธิภาพโดยรวมจะลดลง

3. AI Engineering Decision

หากผมกำลังเทรนโมเดล AI แล้วระบบเกิด Thrashing เนื่องจาก RAM เต็ม ผมจะลองลด batch_size เพื่อให้โมเดลประมวลผลข้อมูลจำนวนน้อยลงในแต่ละรอบ ซึ่งจะช่วยลดปริมาณหน่วยความจำที่ต้องใช้พร้อมกัน
เมื่อโปรแกรมใช้ RAM น้อยลง ระบบปฏิบัติการก็มีโอกาสเก็บ Page ที่จำเป็นไว้ใน RAM ได้มากขึ้น ทำให้ไม่ต้องสลับข้อมูลระหว่าง RAM กับดิสก์บ่อย ๆ จึงช่วยลดปัญหา Thrashing และทำให้การเทรนทำงานได้ต่อเนื่องมากขึ้น
จากการทดลอง ผมเห็นว่าการอ่านและเขียนข้อมูลผ่านดิสก์ซ้ำ ๆ ใช้เวลามากกว่าการประมวลผลข้อมูลใน RAM ดังนั้นการลด batch_size จึงเป็นแนวทางหนึ่งในการลดการใช้หน่วยความจำและหลีกเลี่ยงการทำงานที่ช้าลงจากการสลับข้อมูลไปยังดิสก์
