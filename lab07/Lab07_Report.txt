1. The Convoy Effect (Phase 2):

จากการทดลองผมเข้าใจว่า Convoy Effect คือปัญหาที่ Process ซึ่งใช้เวลาทำงานสั้นต้องรอ Process ที่ใช้เวลาทำงานนานอยู่ข้างหน้า ทำให้เวลารอเพิ่มขึ้นโดยไม่จำเป็น
จากผลการทดลอง FCFS พบว่า P1 ใช้ CPU ทั้งหมด 10 หน่วยเวลาและเริ่มทำงานก่อน ทำให้ P2 ต้องรอ 10 หน่วยเวลา ส่วน P3 ต้องรอ 12 หน่วยเวลา เนื่องจากต้องรอทั้ง P1 และ P2 ทำงานให้เสร็จก่อน
เมื่อเปรียบเทียบกับ Round Robin ที่กำหนด Time Quantum เท่ากับ 3 พบว่า P2 ทำงานเสร็จที่เวลา 5 และ P3 ทำงานเสร็จที่เวลา 8 เพราะระบบแบ่งเวลา CPU ให้แต่ละ Process แทนที่จะให้ P1 ใช้ CPU จนเสร็จก่อน
จากการทดลองนี้ ผมเห็นว่า FCFS อาจทำให้ Process สั้นต้องรอนานหากมี Process ยาวอยู่ข้างหน้า ขณะที่ Round Robin ช่วยให้ Process อื่นได้รับ CPU เร็วขึ้นและลดปัญหา Convoy Effect ในสถานการณ์นี้

2. Choosing the Time Quantum:

กรณีที่กำหนด Time Quantum = 100:
จากการทดลองเพิ่มเติมโดยกำหนด Quantum = 100 ผมสังเกตว่า P1 ทำงานเสร็จที่เวลา 10 จากนั้น P2 เสร็จที่เวลา 12 และ P3 เสร็จที่เวลา 15 โดยมี Average Waiting Time เท่ากับ 7.33 และ Average Turnaround Time เท่ากับ 12.33 ซึ่งเป็นผลลัพธ์เดียวกับ FCFS
เนื่องจาก Quantum มีขนาดใหญ่กว่า CPU Burst Time ของทุก Process ทำให้แต่ละ Process สามารถทำงานจนเสร็จภายในรอบเดียว ส่งผลให้ Round Robin มีพฤติกรรมเหมือน FCFS ในการทดลองนี้
กรณีที่กำหนด Time Quantum = 0.0001:
ผมเข้าใจว่าหากกำหนด Quantum เล็กมาก ระบบจะต้องสลับการทำงานระหว่าง Process บ่อยครั้ง ทำให้เกิด Context Switching Overhead สูง เพราะระบบต้องเสียเวลาบันทึกและเรียกคืนสถานะของ Process ส่งผลให้เวลาที่ใช้ประมวลผลงานจริงลดลง
ดังนั้นการเลือก Time Quantum จึงต้องพิจารณาความสมดุลระหว่างการให้ Process ต่าง ๆ ได้รับ CPU อย่างทั่วถึงกับต้นทุนที่เกิดจาก Context Switching

3. AI Context:

จากการทดลอง ผมสังเกตว่าเมื่อใช้ FCFS ระบบจะประมวลผลคำขอของ User A ที่ต้องการ 10 Tokens ให้เสร็จก่อน แล้วจึงเริ่มประมวลผลคำขอของ User B ที่ต้องการเพียง 2 Tokens ทำให้ User B ต้องรอแม้ว่าจะเป็นงานสั้นก็ตาม
เมื่อเปลี่ยนมาใช้ Round Robin ที่สลับให้บริการครั้งละ 1 Token พบว่า User B สามารถสร้าง Tokens ครบและทำงานเสร็จก่อน User A ได้ เพราะระบบเปิดโอกาสให้แต่ละคำขอได้รับการประมวลผลโดยไม่ต้องรอให้คำขอก่อนหน้าทำงานจนเสร็จทั้งหมด
ผมเข้าใจว่าการจัดคิวแบบนี้ช่วยลดปัญหาคำขอสั้นต้องรอคำขอยาว และช่วยลด Time To First Token (TTFT) เนื่องจากผู้ใช้มีโอกาสได้รับ Token แรกเร็วขึ้น ทำให้ระบบ AI แบบโต้ตอบตอบสนองต่อผู้ใช้ได้ดีขึ้น โดยเฉพาะเมื่อมีผู้ใช้หลายคนส่งคำขอเข้ามาพร้อมกัน
